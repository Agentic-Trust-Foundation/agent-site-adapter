# Site Adapter Roadmap

## Phase 0 — Foundation

- define project charter
- define terminology
- define trust boundary
- define site identity model
- define capability model
- define lifecycle/revocation model
- map ATF integration points
- map Agent-Pay integration points
- document threat model
- identify interoperability requirements

## Phase 1 — Minimal interoperable adapter

Target:
- site identity/integration binding
- capability declaration
- authenticated agent request
- basic service discovery
- clear error semantics
- versioning
- test fixtures
- conformance examples

## Phase 2 — Commerce integration

Potential:
- product/service discovery
- availability
- quote/order intent
- consent
- Agent-Pay authorization handoff

## Phase 3 — Broader service ecosystem

Extend beyond commerce to booking, SaaS, APIs, enterprise and other agent-accessible services.

## Definition of Done for V1

V1 should not be declared complete until:
- security model is documented
- identity binding is testable
- capability declarations are unambiguous
- trust evidence is verifiable
- revocation/versioning are defined
- ATF integration is explicit
- payment handoff does not expand authority
- conformance tests exist
- implementation and protocol boundaries are documented
